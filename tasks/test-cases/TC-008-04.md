# Purpose

Verifies AC4: `claim-req.sh` rejects a known UID when the target REQ owner is a different registered UID.

# Preconditions

- `harness/agent-registry.yml` contains `optimizer-001` and `evaluator-001`.
- `optimizer-001` handles `req_impl`.
- The test creates a temporary REQ file, for example `tasks/req/REQ-998.md`, with `status: req_impl` and `owner: evaluator-001`.
- The temporary REQ file is removed after the test.

# Steps

1. Create the temporary REQ file with `status: req_impl` and `owner: evaluator-001`.
2. Run `AGENT_UID=optimizer-001 bash scripts/claim-req.sh REQ-998`.
3. Capture stdout, stderr, and exit code.
4. Delete the temporary REQ file.

# Expected Result

- Exit code is `1`.
- stderr contains `owner is 'evaluator-001'` or equivalent owner mismatch text.
- stderr includes both the actual owner and the attempted UID.
- stdout does not contain a claimable `OK` message.

# Notes

- The implementation may choose exact wording, but the error must include the actual owner value so the receiving agent can diagnose the handoff.
- `status: req_impl` is intentionally valid for `optimizer-001`; this isolates the owner mismatch failure path from the status/handles validation path.
