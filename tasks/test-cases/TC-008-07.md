# Purpose

Verifies AC6: `check-req-coverage.sh` rejects legacy owner values `claude`, `codex`, and `daniel`, and reports the REQ ID and owner field.

# Preconditions

- The test runs in an isolated temporary repository copy or fixture directory so it can create invalid REQ files without modifying the working tree.
- The fixture includes `scripts/check-req-coverage.sh`, `harness/req-constants.sh`, the active registry, and minimal `tasks/req/` structure.
- The fixture registry does not contain `claude`, `codex`, or `daniel`.

# Steps

1. In the isolated fixture, create three REQ stubs:
   - `REQ-991.md` with `owner: claude`
   - `REQ-992.md` with `owner: codex`
   - `REQ-993.md` with `owner: daniel`
2. Run `bash scripts/check-req-coverage.sh` in the fixture repository root.
3. Capture stdout, stderr, and exit code.

# Expected Result

- Exit code is `1`.
- Output contains an invalid owner error for `REQ-991`, `REQ-992`, and `REQ-993`.
- Each error line includes the field name `owner` and the rejected legacy value.

# Notes

- The test should avoid relying on the real repository's active REQ files so failures are attributable only to the three legacy owner stubs.
