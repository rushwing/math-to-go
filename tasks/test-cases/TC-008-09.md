# Purpose

Verifies AC10: `claim-req.sh` accepts an explicit positional UID argument and does not require `$AGENT_UID` when the positional UID is provided.

# Preconditions

- `harness/agent-registry.yml` contains `optimizer-001`.
- `optimizer-001` handles `req_impl`.
- The test creates a temporary REQ file, for example `tasks/req/REQ-998.md`, with `status: req_impl` and `owner: optimizer-001`.
- The temporary REQ file is removed after the test.

# Steps

1. Create the temporary REQ file with `owner: optimizer-001`.
2. Ensure `AGENT_UID` is unset for the subprocess.
3. Run `bash scripts/claim-req.sh REQ-998 optimizer-001`.
4. Capture stdout, stderr, and exit code.
5. Delete the temporary REQ file.

# Expected Result

- Exit code is `0`.
- stdout contains `OK: REQ-998 is claimable by optimizer-001`.
- stderr is empty.

# Notes

- A companion assertion may set `AGENT_UID=evaluator-001` while passing positional `optimizer-001`; the command should still use the explicit positional UID because the REQ specifies that explicit arguments take precedence.
