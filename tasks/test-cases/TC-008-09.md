# Purpose

Verifies AC10: `claim-req.sh` accepts an explicit positional UID argument and does not require `$AGENT_UID` when the positional UID is provided.

# Preconditions

- `harness/agent-registry.yml` contains `optimizer-001`.
- `optimizer-001` handles `req_impl`.
- The test creates a temporary REQ file, for example `tasks/req/REQ-998.md`, with `status: req_impl` and `owner: optimizer-001`.
- The temporary REQ file is removed after the test.

# Steps

1. Create the temporary REQ file with `owner: optimizer-001`.
2. Ensure `AGENT_UID` is unset for the first subprocess.
3. Run `bash scripts/claim-req.sh REQ-998 optimizer-001`.
4. Capture stdout, stderr, and exit code.
5. Run `AGENT_UID=evaluator-001 bash scripts/claim-req.sh REQ-998 optimizer-001`.
6. Capture stdout, stderr, and exit code.
7. Delete the temporary REQ file.

# Expected Result

- Both commands exit `0`.
- Both stdout streams contain `OK: REQ-998 is claimable by optimizer-001`.
- Both stderr streams are empty.
- The second command succeeds even though `$AGENT_UID` is `evaluator-001`, proving the explicit positional UID takes precedence.

# Notes

- This TC must fail if the implementation ignores the positional UID and reads `$AGENT_UID` exclusively.
