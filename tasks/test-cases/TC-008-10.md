# Purpose

Verifies AC11: `claim-req.sh` dynamically reads UID and handles from the registry selected by `AGENT_REGISTRY`, rather than from an embedded UID table.

# Preconditions

- The test creates a fixture registry file containing only one UID: `test-agent-999`.
- The fixture registry gives `test-agent-999` a `handles` list that includes `req_impl`.
- The main registry does not contain `test-agent-999`.
- The test creates a temporary REQ file, for example `tasks/req/REQ-998.md`, with `status: req_impl` and `owner: test-agent-999`.
- Temporary fixture files are removed after the test.

# Steps

1. Create the fixture registry file with `test-agent-999`.
2. Create the temporary REQ file with `owner: test-agent-999` and `status: req_impl`.
3. Run `AGENT_REGISTRY=<fixture_registry> AGENT_UID=test-agent-999 bash scripts/claim-req.sh REQ-998`.
4. Capture stdout, stderr, and exit code.
5. Run `AGENT_UID=test-agent-999 bash scripts/claim-req.sh REQ-998` without `AGENT_REGISTRY`.
6. Capture stdout, stderr, and exit code.
7. Delete the temporary REQ and fixture registry files.

# Expected Result

- The command with `AGENT_REGISTRY=<fixture_registry>` exits `0`.
- The successful command reports `test-agent-999` as claimable.
- The command without `AGENT_REGISTRY` exits `1`.
- The failing command reports `Unknown UID` for `test-agent-999`.

# Notes

- The second command is the negative control that proves the success path came from the fixture registry, not from a hardcoded fallback.
