# Purpose

Verifies AC12: `harness/req-constants.sh` dynamically derives `REQ_VALID_OWNERS` from the registry selected by `AGENT_REGISTRY`, and `check-req-coverage.sh` consumes that derived owner list.

# Preconditions

- The test runs in an isolated temporary repository fixture, not the real working tree.
- The isolated fixture contains `scripts/check-req-coverage.sh`, `harness/req-constants.sh`, and minimal `tasks/req/`, `tasks/bugs/`, and `tasks/test-cases/` directories.
- The test creates a fixture registry containing only `test-agent-999`.
- The isolated fixture also contains the default `harness/agent-registry.yml` with the standard UIDs `optimizer-001`, `evaluator-001`, and `human-001`, but not `test-agent-999`.
- The test creates one REQ stub with `owner: test-agent-999` and a valid status.
- The main project registry does not contain `test-agent-999`.

# Steps

1. Build the isolated temporary repository fixture.
2. In the fixture, create `harness/agent-registry.fixture.yml` containing `test-agent-999`.
3. In the fixture, create the default `harness/agent-registry.yml` with `optimizer-001`, `evaluator-001`, and `human-001`, excluding `test-agent-999`.
4. In the fixture, create `tasks/req/REQ-998.md` with `owner: test-agent-999`, `status: req_review`, and otherwise valid required frontmatter.
5. From the fixture root, run `AGENT_REGISTRY=harness/agent-registry.fixture.yml bash scripts/check-req-coverage.sh`.
6. From the same fixture root, run `bash scripts/check-req-coverage.sh` without `AGENT_REGISTRY`.
7. Capture stdout, stderr, and exit code for both commands.
8. Remove the temporary fixture.

# Expected Result

- The command with `AGENT_REGISTRY=harness/agent-registry.fixture.yml` exits `0`.
- The successful command prints `REQ coverage check passed`.
- The command without `AGENT_REGISTRY` exits `1`.
- The failing command reports `REQ-998: invalid owner 'test-agent-999'` or equivalent invalid owner text that includes the REQ ID and owner value.

# Notes

- The isolated fixture is required because `check-req-coverage.sh` scans all `tasks/req/REQ-*.md` files under its repository root.
- This TC is the negative-control counterpart to TC-008-10 for `req-constants.sh` and `check-req-coverage.sh`.
